Why Mock 2 is approved: a principal's actual morning routine — check attendance, check fee collection, check who's absent/on leave — currently costs 4 separate module opens with zero rollup anywhere. The screen deliberately shows the same handful of numbers three ways (exact grid, colour ring, trend bar) because a principal reads differently at 7am (scan) than at a board meeting (exact figures) — but every reading still resolves to the same 3 real drill-downs. Every number is either a straight read of an existing endpoint or a small aggregate this spec adds (see §3); nothing here is decorative.

4 · API contracts — 4 already exist, 4 are new

GET /academic/attendance?date=2026-08-18 // existing, but returns BOTH student + staff records mixed — entityType isn't filterable today (staff.js's own /attendance route hardcodes entityType:'staff' server-side; academic's does not filter it at all). Add an `entityType` query param. The SAME endpoint, called with a different `date`, is what powers the date-picker's rewind — no separate "historical" endpoint needed. GET /staff/attendance?date=2026-08-18 // existing, unchanged — already scoped server-side to entityType:'staff', 74 records max GET /staff/leave-requests?status=pending&limit=1 // existing, unchanged — always "now", never re-queried by the date picker (see §3) GET /fee/defaulters // existing, unchanged — always "now", never re-queried by the date picker GET /academic/grades/summary?termId=<latest> // NEW — avoids shipping 30,795 raw Grade docs to the client to render one average + a 5-bucket distribution GET /fee/collection-summary?academicYearId=<current> // NEW — avoids shipping 985 populated FeeAssignment docs to compute one percentage; also returns defaulterCount + overdueTotal so Home doesn't have to fetch and sum the full /fee/defaulters array just for 2 numbers GET /academic/attendance/trend?days=7|30 // NEW — returns up to 30 { date, presentPct } points (7 daily, or 30 pre-bucketed into 4 weekly averages); the raw alternative would ship ~19,000+ records to draw a handful of bars. "Year" makes no call — the client already knows the earliest date and shows the notice in §3 instead. GET /academic/attendance/available-dates?month=2026-08 // NEW — returns which calendar dates in that month have attendance recorded, so the date-picker sheet can grey out the rest instead of guessing

5 · State & logic

// Home — one screen, five parallel reads, gated on permission const canSeeSchoolWide = hasAllPermissions([ 'attendance:read', 'fees:read', 'leave:read', 'grades:read' ]); if (!canSeeSchoolWide) return <TenantDashboard />; // unchanged fallback const [attendanceToday, staffAttendanceToday, leaveTotal, gradesSummary, feeSummary, attendanceTrend] = await Promise.all([...]); const studentRecs = attendanceToday.filter(r => r.entityType === 'student'); const presentPct = round(studentRecs.filter(r => r.status === 'present').length / activeStudentCount * 100); const absentToday = studentRecs.filter(r => r.status === 'absent').length; // attention strip hides any row whose count is 0 — same rule as Inventory's AttentionStrip // Date picker — only re-fetches the date-scoped calls, never the "live queue" ones function onDateSelected(date) { refetch(['attendanceToday', 'staffAttendanceToday', 'gradesSummary'], { date }); // leaveTotal and feeSummary are intentionally NOT refetched — they're "now", not "as of" } // Trend period toggle if (period === 'year' && daysSinceEarliestRecord < 365) { showNotice('Not enough history yet'); // no API call — the client already knows the earliest date } else { fetchTrend({ days: period === '7d' ? 7 : 30 }); }

7 · Errors, empty states, accessibility

SituationWhat happens
No attendance marked yet today (before first period, or a holiday)attendance card reads "Not marked yet", not a misleading 0%
User lacks one of the 4 read permissionsfalls back to today's unchanged TenantDashboard — never a partially-broken Smart view
An attention-strip count is 0 (e.g. zero defaulters)that row hides — same rule as Inventory's AttentionStrip
KPI cards & attention rowsreal <button>/<Link> elements with descriptive aria-labels ("414 fee defaulters, view list"), not divs with onClick
Date picker: a date outside the seeded/school-day rangedisabled in the calendar grid (not just unstyled — aria-disabled, no tap handler), so it can't be selected in the first place
Date picker: viewing a past dateheader shows "viewing a past day" plus an inline banner clarifying fee/leave numbers are still current — never silently implies they're historical too
"Year" period requested with <365 days of historyshows the notice from §3, not an extrapolated or flat line

8 · Definition of done

  • A user holding attendance:read + fees:read + leave:read + grades:read sees the Smart Home instead of the 4 metadata cards
  • Attention strip surfaces today's defaulter / pending-leave / absentee counts, each tapping through to its filtered drill-down
  • Academic, Finance and Staff summary screens each backed by a real endpoint — 2 of them new, both lightweight aggregates
  • Users without full visibility keep seeing today's TenantDashboard, unchanged
  • The trend card's 7D/30D/Year toggle reshapes the chart; Year shows an honest notice rather than invented history
  • The date picker rewinds attendance/academic numbers to any recorded past day, while fee defaulters and leave approvals always stay current
