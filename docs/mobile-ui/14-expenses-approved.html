  1. Queue, not table — same pattern as Leave Requests, one decision at a time.
  2. Budget-in-context. Shows the cost center's spend-to-date and what this expense would push it to — the actual decision-relevant number, computed from data that already exists on Budget.
Why Mock 2 is approved: an approver's real question is "does this fit the budget", and today's screen makes them open Budgets separately to find out. Joining GET /expense/budgets onto the queue card answers it without a second screen.
