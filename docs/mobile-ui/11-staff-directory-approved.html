  1. Department sections replace the department filter — you scroll past the ones you don't need instead of picking from a select first.
  2. On-leave strip. The one cross-department question ("who's out today?") answered without filtering.
Why Mock 2 is approved: at 74 staff, department-grouped sections are genuinely easier to scan than filter-then-scroll (this is not a blanket rule — Students at 1000 needs drill-down navigation instead, per rule 1: match the accelerator to the data shape). The "on leave today" strip needs no new query — employmentStatus: 'on_leave' already exists on StaffMember.

2 · API contracts — every one of these already exists

GET /staff/members?limit=100 // existing endpoint; client groups by department instead of the server paging by 20 // 74 rows is small enough to fetch in one call and group/search client-side {{ "members":[{{ "employeeId","firstName","lastName","designation","department","employmentStatus" }}], "total","pages" }} // "On leave today" strip = client filter: members.filter(m => m.employmentStatus === 'on_leave')
