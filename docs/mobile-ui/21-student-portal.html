Proposed pick: Mock 2. The costs on the desktop are real: four navigations to answer four questions, a red badge on a late arrival that the page itself counts as present, and a grade list that doesn't say 24 of 32 marks are unpublished. Mock 1 fixes none of them. The home screen fixes the first; the finding below fixes the second whichever mock you pick.
Findings (not fixed here):
  • MyAttendancePage.jsx:44 — only present is green. late counts as present in the percentage but shows red; excused shows red too.
  • MyGradesPage.jsx — unpublished grades are filtered out server-side with no hint. A student with 24 pending marks sees an apparently complete list of 8.
  • routes/me.js:108 — attendance is capped at 400 rows with no pagination or date range from the page. Fine for one year (about 200 school days), wrong for several.

2 · API contracts — all four already exist, none changes

GET /me/attendance // [{ _id, date, status }] status: present|absent|late|excused, newest first, max 400 GET /me/fees // { assignments:[{ dueDate, totalAmount, discountAmount, status }], payments:[{ paymentDate, amount, paymentMethod, receiptNumber }] } GET /me/grades // [{ subject:{ name, code }, assessmentType, score, letterGrade }] published only GET /me/timetable // [{ dayOfWeek, periodNumber, startTime, endTime, room, subjectId:{ name, code } }] [] if unpublished GET /me/profile // { isStudent, isStaff, student:{ firstName, lastName, admissionNo, sectionId, status } }

The home screen issues these in parallel with React Query, the same query keys the pages already use (['me','attendance'] and so on), so opening a tab afterwards is a cache hit. /me/profile returns only sectionId, not the "Grade 5-A" label shown in the header, so the build needs either one extra lookup or a small addition to that endpoint. Decide before building.
