3 · Mark Attendance

The screen a class teacher opens 200 times a year, standing in front of 25 children with one hand free. Seven concepts, measured by the same yardstick: taps of setup before the first useful tap. Variant 6 adds the desktop view — the office and the staff room have a keyboard. Variant 7 is the baseline: a plain class list with Present / Absent buttons, nothing to learn, and the smallest possible change from the code that ships today.

Pain today: three native selects gate the roster — date, section (<select> with 40 optgrouped options), subject — that is ~11 taps before a single student appears. The status button then cycles present → absent → late → excused, so "excused" costs 4 taps and a mis-tap costs 3 more. One Save Attendance button at the bottom, no autosave: a dropped connection loses the class silently. Unmarked students are posted as absent by omission.
· real data: Grade 5-A, 21 active students, class teacher Dinesh Kurup
VARIANT 1
Default-present, tap the exceptions SHIP

Optimises: a normal day. Everyone starts present; you only touch the 1–2 who aren't. Direct 1-tap status pills, running counts in the header, undo instead of confirm. 3 taps for a 21-student class.

VARIANT 7 · THE BASELINE
Simple list — Present / Absent SHIP as the default

Optimises: nothing to learn. Pick the class, two buttons on every row, save. It is the paper register with buttons — no defaults, no gestures, no hidden long-press. One tap per child (21 taps, ~55 s) instead of 4 total, and that is the honest trade: slower, but every child is explicitly marked, and it is the smallest change from the code that exists today. Late and Excused sit behind the row's ⋯ so the common case stays two buttons.

Recommendation: ship V5 as the entry point (it deletes all 11 setup taps by reading the timetable) wrapping V1's roster (direct status pills, counts, undo, queued writes), with V3's tile grid as a density toggle for teachers who prefer to eyeball the whole room.
